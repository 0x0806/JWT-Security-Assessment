 JWT Misconfigurations

                    
Common JWT implementation flaws and security misconfigurations

                


                

                    

                        
 No Signature Verification

                        

                            
Issue: Application doesn't verify JWT signatures

                            
Impact: Complete authentication bypass

                            

                                
// Vulnerable code
const payload = jwt.decode(token); // No verification!
if (payload.admin) {
    // Grant admin access
}

                            

                        

                    


                    

                        
 Hardcoded Secrets

                        

                            
Issue: JWT secrets stored in source code

                            
Impact: Token forgery and impersonation

                            

                                
// Vulnerable code
const secret = "mysecretkey"; // Hardcoded!
const token = jwt.sign(payload, secret);

                            

                        

                    


                    

                        
 No Expiration Check

                        

                            
Issue: JWT tokens without expiration or ignored exp claim

                            
Impact: Persistent unauthorized access

                            

                                
// Vulnerable code
const payload = jwt.verify(token, secret);
// No expiration check!
return payload;

                            

                        

                    


                    

                        
 Weak Algorithms

                        

                            
Issue: Using weak or deprecated algorithms

                            
Impact: Cryptographic vulnerabilities

                            

                                
// Vulnerable algorithms
"alg": "HS256" // Weak for some use cases
"alg": "RS256" // Vulnerable to key confusion
"alg": "none"  // No security!

                            

                        

                    


                    

                        
 Algorithm Not Enforced

                        

                            
Issue: Verification trusts the alg the token declares instead of pinning one expected algorithm.

                            
Impact: Opens the door to algorithm confusion and "none" bypass even when the server only ever intended to issue RS256/ES256 tokens.

                            

                                
// Vulnerable code
jwt.verify(token, key); // alg comes from the token itself

// Fix: pin exactly what you issue
jwt.verify(token, key, { algorithms: ['RS256'] });

                            

                        

                    


                    

                        
 Sensitive Data in Payload

                        

                            
Issue: JWTs are base64url-encoded, not encrypted — anyone holding the token can read every claim.

                            
Impact: PII or privilege flags placed in the payload leak to the client, browser history, logs, and any proxy the token passes through.

                            

                                
// Vulnerable payload
{ "sub": "1234", "ssn": "123-45-6789", "internalRole": "finance-admin" }

// Fix: keep the payload to opaque identifiers, look up detail server-side
{ "sub": "1234" }

                            

                        

                    


                    

                        
 Missing Audience / Issuer Validation

                        

                            
Issue: The signature is checked but aud and iss never are.

                            
Impact: A token issued for one service or tenant can be replayed against any other service that trusts the same signing key.

                            

                                
// Vulnerable code
const payload = jwt.verify(token, key);
// No aud/iss check — any token from this issuer works anywhere

// Fix
jwt.verify(token, key, {
    audience: 'api.example.com',
    issuer: 'https://auth.example.com'
});
